# Паспорт проекта «Чистый берег»

## 1. Анализ исходной ситуации

### Проблема

Мониторинг состояния природных и прибрежных территорий требует регулярного выявления проблемных участков, оценки их состояния, работы с данными дзз и оперативной организации мероприятий по устранению экологических проблем.

При этом существуют две основные аудитории:

- сотрудники особо охраняемых природных территорий (ООПТ), которым необходимо получать информацию о проблемных участках, планировать мероприятия и координировать волонтёров;
- волонтёры, которым необходимо понимать, где требуется помощь, проходить подготовку и получать понятный сценарий участия.

Разрозненность этих процессов приводит к тому, что обнаружение экологической проблемы, обучение добровольцев, организация мероприятия и фиксация результата могут существовать независимо друг от друга.

### Целевая ситуация

«Чистый берег» объединяет эти процессы в единую цифровую платформу:

**ДЗЗ обнаруживает проблему → сотрудник ООПТ формирует мероприятие → волонтёр проходит обучение → волонтёр участвует → сотрудник подтверждает участие → волонтёр получает бонусы → пользователь возвращается к дальнейшему участию.**

### Аналоги

К аналогам отдельных частей решения относятся:

- платформы волонтёрских мероприятий;
- системы экологического мониторинга;
- образовательные платформы;
- программы лояльности и геймификации.

Отличие «Чистого берега» заключается в объединении этих механик в единый пользовательский путь.

## 2. Цель проекта, ценностное предложение и пользовательские пути

### Цель

Создать цифровую платформу, которая связывает экологический мониторинг, подготовку волонтёров и реальные мероприятия по очистке природных территорий.

### Ценностное предложение

**Для волонтёра:**

- понятный способ узнать, где нужна помощь;
- короткое обучение перед участием;
- практический тренажёр по работе с данными ДЗЗ;
- участие в реальных экологических мероприятиях;
- статистика личного вклада;
- достижения и бонусы;
- мотивация возвращаться к участию.

**Для сотрудника ООПТ:**

- единая рабочая среда;
- визуализация проблемных участков;
- управление мероприятиями;
- привлечение и координация волонтёров;
- подтверждение участия;
- контроль статистики территории.

### Пользовательский путь волонтёра

1. Регистрация.
2. Выбор роли волонтёра.
3. Прохождение обучения.
4. Изучение теоретических материалов.
5. Выполнение практических заданий.
6. Поиск подходящего мероприятия.
7. Просмотр информации о проблемном участке.
8. Запись на мероприятие.
9. Участие в мероприятии.
10. Подтверждение участия сотрудником ООПТ.
11. Получение бонусов и достижения.
12. Возвращение к следующим мероприятиям.

### Пользовательский путь сотрудника ООПТ

1. Регистрация с использованием специального секрета сотрудника.
2. Вход в кабинет ООПТ.
3. Просмотр территорий и проблемных участков.
4. Просмотр демонстрационного слоя ДЗЗ.
5. Выбор проблемного участка.
6. Создание мероприятия.
7. Управление волонтёрами.
8. Подтверждение фактического участия.
9. Контроль статистики территории.

## 3. Стратегия привлечения, обучения, вовлечения и удержания

### Привлечение

Основная аудитория проекта — пользователи, заинтересованные в экологической деятельности и волонтёрстве.

Основные каналы привлечения:

- образовательные учреждения;
- экологические сообщества;
- партнёрские организации;
- социальные сети;
- экологические мероприятия;
- Telegram-бот проекта.

### Обучение

Перед полноценным участием пользователь проходит интерактивный курс.

Обучение включает:

- теоретические материалы;
- изучение принципов работы с данными дистанционного зондирования Земли;
- интерактивные задания;
- практический тренажёр сравнения изображений;
- последовательное открытие следующих этапов обучения.

Цель обучения — снизить порог входа и подготовить пользователя к осмысленному участию в экологическом мониторинге и мероприятиях.

### Вовлечение

Для вовлечения используются:

- интерактивные задания;
- прогресс обучения;
- достижения;
- статистика активности;
- экологические мероприятия;
- связь результатов обучения с реальными действиями.

### Удержание

Основной механизм удержания:

**участие → подтверждение результата → бонусы → награды → повторное участие.**

В проекте предусмотрена бонусная система. Бонусы начисляются за подтверждённое участие, а не за сам факт записи на мероприятие.

## 4. Мероприятия и механики проекта

Основная механика проекта связывает обнаружение экологической проблемы с реальным мероприятием.

### Основные механики

- создание мероприятий на основе проблемных участков;
- ограничение количества участников;
- запись и отмена записи;
- защита от повторной записи;
- подтверждение фактического участия;
- начисление бонусов после подтверждения;
- достижения;
- статистика активности;
- обучение перед практической деятельностью;
- Telegram-бот.

### Бонусная система

Бонусы являются дополнительным стимулом для повторного участия.

Основная механика:

**подтверждённое участие → начисление бонусов → накопление бонусов → получение награды партнёра.**

В рамках продуктовой концепции предусмотрена возможность получения партнёрских наград, например скидки у компании-партнёра.

Конкретные партнёры и условия программы могут быть подключены на этапе пилотирования.

- кабинет ООПТ;

## 6. Прототип, техническая архитектура, данные, технологии и интеграции

### Архитектура

Проект состоит из нескольких основных компонентов:

```text
                    ┌─────────────────┐
                    │    Frontend     │
                    │ React + Vite    │
                    └────────┬────────┘
                             │ REST API
                             ▼
                    ┌─────────────────┐
                    │     Backend     │
                    │ Express + JWT   │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │     MongoDB     │
                    └─────────────────┘

                    ┌─────────────────┐
                    │ Telegram Bot    │
                    │   Telegraf      │
                    └─────────────────┘
```

### Frontend

- React 19;
- React Router;
- MobX;
- Axios;
- Vite;
- Tailwind CSS.

### Backend

- Node.js;
- Express;
- MongoDB;
- Mongoose;
- JWT;
- bcrypt;
- express-validator;
- Nodemailer;
- cookie-parser;
- CORS.

### Telegram-бот

- Node.js;
- Telegraf;
- dotenv.

### Основные модели данных

- User;
- UserProgress;
- Education;
- Achievement;
- EventRegistration;
- ProblemArea;
- BonusTransaction;
- Reward;
- RewardRedemption;
- Token.

### API

Основные API-группы:

- `/api/auth`;
- `/api/education`;
- `/api/events`;
- `/api/achievements`;
- `/api/activity`;
- `/api/volunteer`;
- `/api/territory`.

Для сотрудников ООПТ предусмотрены защищённые endpoints управления территориями, мероприятиями и участниками.

### Данные ДЗЗ

В MVP используется демонстрационный источник данных.

Контракт данных ДЗЗ предусматривает:

- источник;
- изображение;
- координаты;
- дату;
- тип данных;
- обнаруженные объекты;
- confidence.

Архитектура позволяет заменить демонстрационный источник реальным API без изменения основной логики frontend.

## 7. KPI и способ их измерения

На этапе пилотирования предлагается использовать следующие показатели.

### Привлечение

- количество зарегистрированных пользователей;
- доля пользователей, завершивших регистрацию;
- количество новых пользователей за период.

### Обучение

- доля пользователей, начавших обучение;
- доля пользователей, полностью завершивших обучение;
- средний процент правильных ответов;
- среднее время прохождения курса.

### Вовлечение

- количество записей на мероприятия;
- доля пользователей, дошедших от обучения до записи;
- количество фактических участников;
- доля повторных участников.

### Экологический результат

- количество проведённых мероприятий;
- количество очищенных территорий;
- количество подтверждённых волонтёрских участий;
- количество обработанных проблемных участков.

### Удержание

- доля пользователей, вернувшихся к повторному участию;
- количество пользователей, использовавших бонусы;
- среднее количество мероприятий на одного активного пользователя.

## 8. План реализации, роли, ресурсы и основные статьи затрат

### Этап 1. MVP

Реализованы:

- авторизация;
- роли волонтёра и сотрудника ООПТ;
- обучение;
- тренажёр;
- мероприятия;
- проблемные участки;
- демонстрационный слой ДЗЗ;
- кабинет ООПТ;
- достижения;
- бонусная система;
- Telegram-бот.

### Этап 2. Пилотирование

Планируется:

- подключение реального источника ДЗЗ;
- подключение реальных территорий;
- пилот с одной или несколькими ООПТ;
- подключение первых партнёров;
- сбор продуктовой аналитики;
- тестирование пользовательских сценариев.

### Этап 3. Масштабирование

Планируется:

- расширение количества территорий;
- подключение новых регионов;
- автоматизация анализа снимков;
- расширение аналитики;
- интеграция с внешними системами;
- развитие мобильного клиента.

### Роли

Для развития продукта необходимы:

- product/project manager;
- frontend-разработчик;
- backend-разработчик;
- специалист по ДЗЗ и геоданным;
- UX/UI-дизайнер;
- специалист по взаимодействию с ООПТ;
- специалист по партнёрствам и привлечению волонтёров.

### Основные статьи затрат

- разработка и сопровождение;
- серверная инфраструктура;
- хранение данных;
- обработка спутниковых снимков;
- домен и сетевые сервисы;
- коммуникации и продвижение;
- организация экологических мероприятий;
- партнёрская программа.

На стадии MVP значительная часть затрат снижается за счёт использования демонстрационных данных и существующих open-source технологий.

## 9. Допущения, ограничения и риски

### Допущения

- пользователи готовы проходить короткое обучение перед участием;
- ООПТ заинтересованы в цифровой координации волонтёров;
- данные ДЗЗ могут использоваться для предварительного выявления проблемных участков;
- партнёрская бонусная программа может повысить повторное участие.

### Ограничения MVP

- данные ДЗЗ являются демонстрационными;
- часть демонстрационных данных хранится в упрощённом виде;
- отсутствует полноценная промышленная интеграция с реальными спутниковыми системами;
- Telegram-бот является демонстрационным компонентом;
- промышленное масштабирование инфраструктуры не является целью MVP.

### Основные риски

#### Низкая вовлечённость пользователей

Меры:

- геймификация;
- бонусы;
- короткое обучение;
- понятный пользовательский путь;
- партнёрские награды.

#### Недостаточная точность определения загрязнений

Меры:

- использование ДЗЗ как инструмента предварительного мониторинга;
- верификация специалистом;
- накопление истории наблюдений;
- подключение специализированных моделей анализа.

#### Недостаток реальных данных

Меры:

- интеграция с внешними источниками ДЗЗ;
- постепенное расширение набора территорий;
- пилотирование на ограниченном количестве ООПТ.

#### Низкая готовность ООПТ использовать новую систему

Меры:

- пилот с одной территорией;
- минимизация количества действий сотрудника;
- обучение сотрудников;
- сбор обратной связи.

#### Накрутка активности

Меры:

- запрет повторной записи;
- защита от повторной подачи одной заявки;
- начисление бонусов только после подтверждения фактического участия сотрудником ООПТ.

#### Утечка секретов и учётных данных

Меры:

- хранение секретов только в переменных окружения;
- использование `.env.example` без реальных значений;
- исключение `.env` из Git;
- ротация секретов перед публикацией;
- отсутствие секретов в публичном репозитории.

## 10. Ожидаемый результат и эффект

### Результат

Создание единой цифровой платформы, связывающей:

**мониторинг → обучение → волонтёрское мероприятие → подтверждение результата → мотивацию → повторное участие.**

### Для волонтёров

- более понятный вход в экологическое волонтёрство;
- получение практических знаний;
- возможность видеть реальный результат своей деятельности;
- система достижений и бонусов;
- повышение вероятности повторного участия.

### Для ООПТ

- цифровизация координации волонтёров;
- единая информация о проблемных участках;
- упрощение создания мероприятий;
- контроль фактического участия;
- накопление статистики.

### Для природных территорий

- более оперативное выявление потенциальных проблем;
- увеличение числа организованных экологических мероприятий;
- повышение вовлечённости добровольцев;
- формирование постоянного сообщества участников.

### Долгосрочный эффект

В перспективе «Чистый берег» может стать цифровой инфраструктурой, объединяющей экологический мониторинг, гражданскую активность и работу ООПТ.
